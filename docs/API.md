# REST API v1

Локальный базовый адрес: `http://localhost:5180`. Секреты CRM не передаются клиентам.

## POST /api/leads

`Content-Type: application/json`, максимум 8192 байта, не более 5 попыток на IP в минуту. Ограничение применяется до валидации.

```json
{"name":"Тестовый клиент","phone":"+7 (000) 000-00-00","comment":"Учебная заявка"}
```

| Поле | Требование |
|---|---|
| `name` | Строка, 2–80 UTF-16 единиц после Trim; обязательно |
| `phone` | Строка, 10–15 ASCII-цифр, необязательный начальный `+`, допустимы пробелы, `-`, `(`, `)` |
| `comment` | Строка или null, максимум 1000 UTF-16 единиц до Trim; необязательно |

Ответ `201 Created`:

```json
{"success":true,"leadId":123,"message":"Заявка успешно отправлена"}
```

ID — положительное число, полученное от CRM, не локальный счётчик. Location не указывается: публичного маршрута получения отдельного лида в MVP нет.

Ответ `400 Bad Request`:

```json
{
  "success": false,
  "code": "VALIDATION_ERROR",
  "errors": {
    "name": ["Имя должно содержать от 2 до 80 символов"],
    "phone": ["Телефон должен содержать от 10 до 15 цифр; допустимы начальный +, пробелы, дефисы и скобки"]
  }
}
```

Невалидный JSON или JSON другого типа возвращает ошибки поля `body`. Запросы с неверным Content-Type возвращают 415, превышение размера — 413. При низкоуровневом отказе HTTP-сервера запрос может быть отклонён до обработки endpoint.

## GET /api/leads?start=0

**Только Development**. `start` — необязательное неотрицательное целое Int32, по умолчанию 0. Пустое, повторное, отрицательное или нечисловое значение возвращает 400 с ошибкой `start`.

```json
{
  "items": [{
    "id":123,
    "title":"Заявка с сайта — Тестовый клиент",
    "name":"Тестовый клиент",
    "phone":"+70000000000",
    "comments":"Учебная заявка",
    "createdTime":"2026-11-10T12:00:00+03:00"
  }],
  "total": 1,
  "nextStart": null
}
```

Для следующей страницы передайте полученный `nextStart` как `start`. При null следующей страницы нет. Размер страницы задаёт CRM, обычно до 50 элементов. Строковые поля и дата могут быть null, если CRM не вернула их; телефон выбирается из первого `fm` с `typeId: "PHONE"`.

В Production и Staging GET не регистрируется. ASP.NET Core возвращает 405, поскольку POST по тому же пути существует. Запрос не доходит до CRM. Полный исходный JSON CRM клиенту не возвращается.

## GET /health

`200 OK`:

```json
{"status":"healthy"}
```

Маршрут подтверждает работу приложения после проверки конфигурации при запуске. Он не проверяет CRM и вебхук.

## Ошибки интеграции

```json
{"success":false,"code":"BITRIX_API_ERROR","message":"Не удалось передать заявку в CRM"}
```

| HTTP | Код | Причина |
|---|---|---|
| 429 | `RATE_LIMIT_EXCEEDED` | Локальный лимит; заголовок `Retry-After: 60` |
| 429 | `BITRIX_RATE_LIMIT` | HTTP 429 от CRM |
| 502 | `BITRIX_API_ERROR` | Ошибки прав/авторизации, `error` в JSON, невалидный результат или JSON |
| 503 | `BITRIX_UNAVAILABLE` | Ошибка транспорта или HTTP 5xx CRM, кроме тайм-аута |
| 504 | `BITRIX_TIMEOUT` | Тайм-аут HttpClient или HTTP 408/504 от CRM |
| 500 | `INTERNAL_ERROR` | Неожиданная ошибка приложения без раскрытия подробностей |

Автоматических повторов нет. Для 503/504 и разрыва связи проверьте CRM перед повторной отправкой: предыдущий запрос мог завершиться созданием лида.

Swagger UI: `/swagger/index.html`. Машиночитаемый контракт: `/swagger/v1/swagger.json`. Оба доступны только в Development.
